# 0001 디지털 트윈 우선 개발

날짜: 2026-11-17
상태: 채택

## 결정

1. 디지털 트윈을 서버·사이드 패널보다 먼저 개발한다.
2. 트윈 개발 동안 씬은 MQTT `bus` 대신 픽스처 재생기가 채운 store를 읽는다. 픽스처는 토픽 메시지를 그대로 녹화한 JSONL이고, 나중에 `tools/play.py`가 같은 파일을 브로커로 재생한다.
3. 3D 품질의 참조는 realvirtual WEB 공개 데모다. 코드는 AGPL-3.0이므로 복사하지 않는다.
4. 품질 기준이 "로우폴리, 조명 베이크"에서 "PBR 재질, HDRI 환경광, 실시간 그림자, SSAO"로 바뀐다. 태블릿용 low 등급을 따로 둔다.
5. site-config의 스키마는 메시지 스키마와 같이 `contracts/schemas/`에 둔다.

## 이유

- 사이드 패널과 서버는 가리킬 대상(사이트, 셀, 로봇)과 이름 규칙이 먼저 있어야 한다.
- 픽스처로 개발하면 서버가 없어도 트윈을 끝까지 검증할 수 있고, 같은 픽스처가 통합 테스트 자료가 된다.
- 씬이 store만 읽으므로 나중에 `bus`로 바꿔도 씬 코드는 바뀌지 않는다.

## 영향

- 프론트의 작업 순서가 바뀐다: `scene/`과 트윈 랩이 `panel/`보다 먼저다.
- 트윈이 쓰는 토픽의 스키마를 M0에서 먼저 확정해야 한다.
- 에셋 제작 시간이 늘어난다. 일정의 대부분이 M3(모델링)에 든다.
