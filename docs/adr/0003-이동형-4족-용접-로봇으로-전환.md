# 0003 고정형 셀 로봇에서 이동형 4족 자석발 용접 로봇으로

날짜: 2026-11-18
상태: 채택. 1단계 로봇 모델, 2단계 계약, 3·5단계 환경과 면 위 용접선 완료(2026-11-18). 6단계 씬 일부 남음.

## 결정

시나리오의 용접 로봇을 바꾼다. 셀 바닥에 고정된 큰 6축 로봇이 정해진 작업판만 용접하는 그림이 아니다. 인간 용접공을 대신해 선체 블록 안을 스스로 걷고, 수직벽·곡면 강판에 자석발로 붙어 용접하는 4족 로봇이다.
조선소용 4족 자석발 작업 로봇(사족 보행 플랫폼 위에 협동 용접 로봇을 얹은 구성)을 참고해 대역 모델 `spider-welder`를 만든다.

- 생성기: `digital-twin/assets/gen/spider.py`(make_robot.py가 부른다). 링크별 STL + URDF. 손으로 고치지 않는다.
- 관절: 다리 4개 × (hip_yaw, hip_pitch, knee, ankle_pitch, ankle_roll) + 팔 arm_1~arm_6 + 토치(고정). 발목 두 축은 실물에서 수동 관절이지만 자세를 보이려고 revolute로 둔다.
- 관절 0° = 서 있는 자세. 네 발판이 몸통 중심 아래 0.14m 평면에 평평하게 닿는다. 로봇 랩 L3(`harness/e2e/robot.spec.ts`)가 바닥·벽 두 경우를 확인한다.
- 치수는 공개 사진으로 어림했다(공개 사양: 로봇 약 15kg, 가반하중 30kg, 전자영구자석 발). 실제 기종 CAD가 오면 관절 이름을 맞춰 교체한다.
- 기존 `standin-6axis`와 조선소·공장 사이트는 그대로 둔다. 새 로봇은 로봇 랩(`/lab/robot`)에서 먼저 본다.

## 이유

- 조선소 블록 내부(이중저, 론지·늑판 사이)는 좁고 장애물이 많아 고정형 로봇이 들어갈 수 없다. 사람이 하던 일을 대신하려면 로봇이 작업 위치로 이동해야 한다.
- 3D 트윈의 가치도 바뀐다. "로봇이 어디에 있고, 어느 용접선을 맡고, 어디로 가는가"를 보여 주는 것이 관제의 중심이 된다.

## 영향과 다음

트윈의 기존 가정 몇 개가 맞지 않게 된다. 아래 순서로 바꾼다. 각 단계는 이 ADR을 근거로 한다.

1. **로봇 모델**(완료): 대역 4족 로봇, 로봇 랩, L3 검사.
2. **계약**(완료): 토픽의 `{cell}` = 로봇 id(사용자 결정). `robot/state`에 선택 필드 `base`(몸통 자세: 사이트 좌표 위치 m, 쿼터니언 xyzw, 붙은 surface id)와 `contacts`(발 링크 → 자석 붙음)를 더했다. 별도 `robot/pose` 토픽 대신 같은 메시지에 넣은 이유: 관절각과 몸통 자세가 같은 시각의 한 자세라 따로 오면 보간 시각이 어긋난다.
   site-config에 `surfaces`(용접선이 놓이는 강판 면, 3D 자세)를 더하고 셀의 `plate`를 선택으로 바꿨다. `task/proposal`·`task/snap`은 선택 `surface`로 면을 가리킨다. 모두 선택 필드라 `v`는 1 그대로이고 기존 사이트·픽스처는 바뀌지 않는다. 계약 문서: `contracts/docs/README.md` "작업 단위".
3. **환경**(완료): 새 사이트 `ship-block`(이중저 블록 내부: 외판, 론지, 맨홀 있는 늑판·중심 거더, 측면 외판). 옛 `shipyard`(고정 셀)는 처음엔 검사·기준 이미지를 지키려고 남겼다가, 검사를 ship-block 시나리오 픽스처(같은 시간표)로 옮기고 지웠다(2026-11-18). 고정 로봇 경로는 `factory`가 검사한다. 곡면 외판은 아직 없다(면 계약이 평면이다).
4. **"셀" 개념**(2단계에서 결정): 셀 = 작업 단위 = 로봇 1대. 이름은 호환을 위해 `cells`로 두고, 작업 위치는 `surfaces`로 분리했다. 코드 전반의 `cell` → `unit` 이름 변경은 필요해질 때 따로 한다.
5. **용접선 좌표**(완료, 평면만): 경로의 `surface`가 가리키는 면 위에 그린다. 바닥 외판과 수직 측면 외판에서 확인. 곡면은 면 계약을 넓혀야 한다.
6. **씬**: 로봇이 base를 따라 움직이고 비콘·라벨·알람이 붙어 다닌다(완료). 그림자 범위는 surfaces를 감싼다(완료). 로봇 여러 대일 때 드로우 콜: 링크마다 재질별 메시를 하나로 합쳐(팔레트 텍스처) 스파이더 1대 약 128 → 56으로 줄였다(완료). 로봇 따라가기 카메라(선택한 로봇, IX-07), 발 접촉 표시(발판 고리, DY-12) 완료. 남은 것: 이동 경로(계획) 표시. 계약에 경로 메시지가 아직 없다.
