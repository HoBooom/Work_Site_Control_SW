# 0004 MQTT 연결(M5)과 개발용 브로커

날짜: 2026-11-18
상태: 채택

## 결정

- 웹은 브라우저에서 MQTT over WebSocket(포트 9001)으로 브로커에 붙는다. `frontend/src/bus/mqtt-bus.ts`가 `innoworks/{site}/#`을 구독하고, 셀 토픽 payload를 계약 스키마(`contracts/schemas`, ajv)로 검사해 맞는 것만 store에 넣는다. 틀린 메시지는 경고를 남기고 버린다. 씬과 store는 픽스처 재생 때와 같다.
- 엣지(MIC-711D)의 브로커는 mosquitto다(`infra/mosquitto.conf`: TCP 1883, WebSocket 9001, retained 영속).
- 맥 개발과 검사는 같은 포트의 Node 브로커 aedes를 쓴다(`infra/broker.mjs`). 시스템 설치가 없고, 검사(`harness/e2e/mqtt.spec.ts`)가 빈 포트에 브로커를 스스로 띄워 다른 PC·CI에서도 돈다(사용자 결정).
- 서버가 없을 때는 `tools/play.mjs`가 픽스처를 브로커로 재생해 서버 역할을 한다. 원래 계획의 `play.py` 대신 Node로 썼다: 프론트와 같은 mqtt.js를 쓰고, 검사가 같은 함수를 불러 재생과 비교할 수 있다.
- 재생기는 셀마다 연결을 열고 유언(LWT) `status=offline`(retained)을 건다. 시작할 때 그 셀들의 계약상 retained 토픽을 모두 비운다(앞 재생의 상태가 섞이지 않게).
- 트윈 랩은 `source=mqtt&broker=ws://…`로 실시간 모드가 된다. 시계는 실제 경과 시간이고 bus의 수신 시각과 같은 시계다. 관제 웹앱 첫 화면(`/`)은 브로커에 붙은 실시간 트윈이다.

## 검증(M5 끝나는 조건)

`mqtt.spec.ts`(L3):
- 시나리오 픽스처 5개를 여러 시각까지 브로커로 재생한 store 상태가, 같은 시각의 픽스처 재생 store 상태와 같다(수신 시각만 빼고 모든 필드).
- 화면을 늦게 열어도 retained로 지금 상태가 보인다. 재생기가 비정상 종료하면 유언으로 셀이 오프라인(회색)이 된다.
- 계약에 맞지 않는 메시지는 버리고 경고한다. 실시간 재생(4배속)에서 로봇이 걷고 작업이 끝난다. 관제 화면이 브로커 상태로 트윈을 그린다.

## 열린 문제(서버 단계에서 정한다)

- **셀별 LWT**: 계약은 `{cell}/status`를 셀마다 둔다. MQTT 연결 하나에 유언은 하나라서, 서버가 셀마다 연결을 하나씩 열거나, 사이트 단위 서버 상태 토픽(예: `innoworks/{site}/server/status`)을 더해야 한다. 재생기는 앞의 방식으로 흉내 냈다.
- **인증·TLS**: 지금은 현장 LAN 안 익명 접속. 운영 전 사용자·ACL·TLS를 정한다.
- **명령(cmd/*)**: 웹 → 서버 발행은 아직 없다. 사이드 패널과 함께 bus에 발행을 더한다(계약 먼저).
- **태블릿 확인**: low 등급 성능(L5)은 통과. 실제 태블릿에서 관제 화면 터치 조작을 사람이 확인한다.
