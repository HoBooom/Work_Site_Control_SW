# 관제 웹앱 기능명세(프론트, 서버 전)

디지털 트윈(M0~M5) 다음 단계다. 사람이 AI가 제안한 용접선을 보고, 필요하면 고치고, 승인해 로봇을 움직이고, 결과를 확인하는 흐름(HITL)을 웹에서 끝까지 만든다.
서버보다 먼저 만든다. 서버 자리에는 **MQTT Mock 서버**(`tools/mock-server.mjs`)를 두고, 카메라 자리에는 **임의의 사진**을 둔다(사용자 결정, 2026-11-18). 실제 카메라·로봇 연결은 맨 뒤다.

검증 방법은 이 문서 7절, 화면 구조는 [README.md](README.md).

## 1. 목표와 끝나는 조건

노트북과 태블릿에서 아래가 Mock 서버만으로 끝까지 돈다.

1. 3D 트윈에서 로봇을 누르면 사이드 패널에 그 로봇의 카메라 영상과 AI 제안 경로(붉은 선), 신뢰도가 뜬다.
2. **승인**하면 로봇이 용접하고(트윈에서 걷고 아크가 켜진다), 패널에 진행률이 오르고, 끝나면 **확인**(합격·재작업)을 누른다.
3. **수정**을 누르면 영상이 멈추고, 손가락·마우스로 선을 다시 그린다. 손을 떼면 서버가 용접선으로 수렴시킨 결과가 돌아오고, 다시 승인할 수 있다.
4. **긴급정지**는 두 가지다. 상단에 고정된 **전체 긴급정지**는 사이트의 모든 로봇을, 패널의 **이 로봇 정지**는 그 로봇만 멈춘다. **재개**로 돌아온다.
5. 알람이 목록에 쌓이고, 누르면 그 로봇으로 간다. 서버·브로커와 끊기면 화면 전체에 표시되고, 다시 붙으면 복구된다.

지켜야 할 것(README "핵심 규칙"): 명령을 보낸 뒤 화면을 미리 바꾸지 않는다. 버튼 활성화는 서버 상태로만 정한다. 경로는 원본 프레임 픽셀로 보관한다.

## 2. 화면

```
┌ 상단: 사이트 이름 · 연결 상태 · 운영자 ───────────────────────[긴급정지]┐
│ 3D 트윈(선택한 로봇 강조, 카메라가 따라감)      │ 사이드 패널(선택한 로봇)       │
│                                              │  상태 배지 · 작업 id            │
│                                              │  카메라 영상 + 경로 오버레이    │
│                                              │  [수정] [승인] / [확인 합격·재작업] │
│                                              │  진행률 · 신뢰도 · 추론 지연     │
├ 알람 목록(심각도, 시각, 로봇, 메시지 · 누르면 그 로봇으로) ────────────────┤
└──────────────────────────────────────────────────────────────────┘
```

- 노트북(가로 1280 이상): 트윈과 패널을 나란히. 태블릿(가로 1180 안팎): 같은 배치, 패널 폭을 줄인다. 세로 화면: 패널이 아래에서 올라오는 시트가 된다.
- 로봇을 고르지 않았으면 패널에 로봇 목록(상태별)을 보인다.

## 3. 작업 상태와 명령(Mock 서버가 따르는 규칙 = 서버 명세 초안)

상태는 `task/state`의 7개(contracts). 명령은 웹 → 서버 `innoworks/{site}/{cell}/cmd/{이름}`.

| 명령 | 받는 상태 | 결과 |
| --- | --- | --- |
| `edit_start` | proposed | editing. 서버가 지금 프레임을 멈춰 `frame_id`로 알린다 |
| `drag` | editing | 서버가 경로를 수렴시켜 `task/snap`을 보내고, 성공이면 그 경로로 다시 proposed |
| `approve` | proposed | running. 로봇이 경로를 따라 용접, `task/progress` |
| `confirm` | completed | 결과(합격·재작업)를 기록하고 idle. 재작업이면 같은 자리를 다시 제안 |
| `estop` | 아무 상태 | estopped + 치명 알람. 셀 토픽이면 그 로봇만, 사이트 토픽 `innoworks/{site}/cmd/estop`이면 모든 로봇 |
| `resume` | estopped, paused | 하던 작업이 있으면 승인 대기(proposed, 남은 경로)로, 없으면 idle. 셀 토픽이면 그 로봇만, 사이트 토픽이면 모든 로봇 |

- 허용되지 않은 상태의 명령은 거부하고 `alarm`(CMD_REJECTED, warning)을 보낸다. 상태는 그대로.
- 웹 heartbeat(1초)가 3초 넘게 끊기면 running 로봇을 paused로(HEARTBEAT_LOST 알람).
- 이 표는 서버 단계의 `server/docs/state-machine.md`로 옮긴다. Mock과 서버가 같은 표를 따른다.

## 4. 계약에 더할 것(contracts부터 고친다)

| 무엇 | 내용 |
| --- | --- |
| `cmd-*` 스키마 6개(긴급정지·재개는 셀 토픽과 사이트 토픽 둘 다) | 공통 `v, ts, cmd_id(웹이 만든 uuid), operator`. `task_id`(estop 제외). `drag`: `frame_id`, `path_px`([[x, y]...], 원본 프레임 픽셀). `confirm`: `result`(ok, rework) |
| `task/proposal`, `task/snap` | 선택 필드 `frame_id`, `path_px`, `frame_size`([w, h]). 패널은 픽셀 경로를, 트윈은 mm 경로를 그린다 |
| `alarm` | 선택 필드 `cmd_id`(어느 명령이 거부됐는지) |
| `vision/metrics` | `latency_ms`, `confidence`, `disturbance`(0~1) |
| `heartbeat` | `innoworks/operator/{client_id}/heartbeat`: `v, ts, site` |
| HTTP | `/stream/{cell}`(영상), `/frames/{frame_id}`(멈춘 프레임). Mock 서버가 사진으로 내준다. 개발 서버(Vite)가 이 경로를 Mock 서버로 넘긴다 |

픽셀 ↔ mm 변환은 서버가 한다(contracts 좌표계). Mock은 사진마다 적어 둔 대응점 4개로 호모그래피를 만든다.

## 5. Mock 서버(`tools/mock-server.mjs`)

- 3절 표대로 셀마다 상태 머신을 돌리고 MQTT로 상태·제안·수렴·진행률·알람·메트릭을 보낸다. 유언(LWT)은 셀마다.
- 로봇 움직임(`robot/state`)은 픽스처의 구간을 다시 쓴다(대기, 걷기, 용접: `ship-block-weld`·`-basic`의 robot/state). 진행률에 맞춰 용접 구간을 재생한다.
- 영상: `tools/mock-frames/{이름}.jpg` + `{이름}.json`(사진 크기, 용접선 픽셀 꺾은선, 면 위 mm 대응점 4개). 처음엔 임의의 사진 1~2장. 실제 카메라가 오면 이 자리를 서버의 카메라로 바꾼다.
- 수렴(`drag`)은 사용자가 그린 선을 사진의 용접선에 가장 가까운 점들로 붙인다(실제 수렴 알고리즘은 서버 `snap/`).

## 6. 기능 목록

| ID | 기능 | 완료 기준 | 검증 |
| --- | --- | --- | --- |
| UI-01 | 레이아웃: 트윈 + 사이드 패널 + 알람 목록 + 고정 긴급정지. 노트북·태블릿·세로 | 세 크기에서 겹치거나 잘리지 않는다 | L3, L4 |
| UI-02 | 선택 → 패널: 트윈에서 로봇·알람 누르기, 패널 로봇 목록에서 고르기 | 셋 다 같은 선택 상태가 된다 | L3 |
| UI-03 | 카메라 뷰 + 경로 오버레이: 영상 위 canvas에 `path_px`를 그린다. 화면 크기가 바뀌어도 맞는다 | 그린 점이 원본 픽셀 변환과 1px 이내 | L3, L4 |
| UI-04 | 작업 제어: 상태별 버튼(수정·승인·확인·재개). 활성화는 서버 상태로만. 보낸 뒤 응답 전에는 대기 표시 | 상태 7개 × 버튼 활성화 표가 맞다. 보낸 직후 상태가 안 바뀐다 | L2, L3 |
| UI-05 | 수정 모드: 프레임 정지, Pointer Events로 그리기(마우스·터치), 손 떼면 `cmd/drag` 한 번, 수렴 결과 표시 | 드래그 한 번에 명령 한 번. 수렴 경로가 그려진다. 스크롤이 안 된다 | L3, L4 |
| UI-06 | 긴급정지·재개: 전체 긴급정지(모든 화면 고정)와 로봇별 정지, 확인 없이 즉시 발행 | 전체는 모든 로봇이, 로봇별은 그 로봇만 estopped | L3 |
| UI-07 | 알람 목록: 심각도순·최신순, 활성·해제, 누르면 그 로봇 선택 | 알람 수와 목록 수가 같다 | L3 |
| UI-08 | 연결 상태: 브로커 끊김·서버 오프라인을 화면에 표시, 복구 | 끊으면 표시, 다시 붙으면 사라지고 상태 복구 | L3 |
| UI-09 | 메트릭: 신뢰도·추론 지연·외란 | 받은 값이 보인다 | L3 |
| UI-10 | heartbeat 발행(1초), 운영자 id | Mock이 끊김을 감지해 paused로 바꾼다 | L3 |

## 7. 검증(하네스)

트윈 하네스(`digital-twin/harness`)를 같이 쓴다. 브로커와 Mock 서버는 검사가 빈 포트에 스스로 띄운다.

| 단계 | 무엇 |
| --- | --- |
| L0 | 계약 예시(cmd 포함), 타입, lint |
| L2 | 버튼 활성화 표, 경로 픽셀 변환, Mock 상태 머신(모든 전이와 거부) |
| L3 | 시나리오: 제안 → 승인 → 완료 → 확인, 수정(드래그 → 수렴 → 재승인), 거부 알람, 긴급정지·재개, heartbeat 끊김, 브로커 끊김·복구. `window.__app`으로 상태를 확인한다 |
| L4 | 패널 상태별 기준 화면(제안, 수정 중, 실행 중, 완료, 긴급정지)과 태블릿 크기 |
| H | 태블릿에서 터치로 수정하기 |

## 8. 마일스톤

| 단계 | 내용 | 끝나는 조건 |
| --- | --- | --- |
| F0 | 계약(cmd, 경로 픽셀, 메트릭, heartbeat) + Mock 서버 뼈대(상태 머신, 사진 영상) + 레이아웃 | 상태 머신 L2 통과, 화면이 뜬다(완료 2026-11-18, ADR 0005) |

| F2 | 수정 모드(정지 프레임, 드래그, 수렴) | 수정 시나리오 L3, 기준 화면 승인(완료 2026-11-19) |

| F4 | 메트릭, 태블릿·세로 배치 | L4 승인, 태블릿 사람 확인 |
| F5(나중) | 실제 카메라·로봇: 서버 단계에서 Mock 서버를 FastAPI 서버로 바꾼다 | 같은 L3가 실제 서버로 통과 |

## 9. 정해지지 않은 것

| 항목 | 정해질 때까지 |
| --- | --- |
| 카메라 위치(로봇 몸통? 팔? 고정?)와 화각 | 임의의 사진. 영상 1개 = 로봇 1대 |
| 운영자 로그인 | 지금은 만들지 않는다. 운영자 id는 브라우저마다 만든 값(사용자 결정) |
| 확인 결과의 종류 | 합격·재작업 두 가지(사용자 결정) |
| 긴급정지 범위 | 로봇별과 사이트 전체 둘 다(사용자 결정) |
| 영상용 사진 | 생성기로 만든 강판·용접선 그림(사용자: 아무거나). 실제 사진은 같은 자리에 넣으면 된다 |
