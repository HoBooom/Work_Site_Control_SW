# 프론트 개요 (아키텍처)

노트북과 태블릿에서 같이 쓰는 관제 웹앱이다. 배치와 겉모습은 디자인 시안 Welding Control v3와 `frontend/DESIGN.md`를 따른다(ADR 0006: 파랑은 주 동작, 빨강은 멈춤에만). 3D 트윈에서 로봇과 알람을 고르고, 사이드 패널에서 경로를 승인·수정한다. React + Vite + TypeScript, R3F + drei, Zustand, mqtt.js.

## 화면 구성

```
┌ 상태 줄: 로고 · 사이트 이름 ······· 시계 · 연결 상태 · 운영자 ┐
│ 사이드 패널 │손│ 3D 트윈                     [전경|스파이더 1|2] │
│  로봇 목록  │잡│  ┌ 알람 카드 ┐                              │
│  또는 로봇  │이│  └──────────┘                               │
│  (영상·경로·│  │                                             │
│   버튼)     │  │                                             │
├ 하단 독: [스파이더 1][스파이더 2][알람 n] ········ [전체 긴급정지] ┤
```

## 계층

```
frontend/src/
├─ app/       관제 웹앱(/): 화면 틀(상태 줄·패널·손잡이·트윈·하단 독), bus 연결, heartbeat, window.__app
├─ bus/       MQTT 연결·재연결, 구독, 계약 스키마 검증, 명령 발행(cmd/*, 보내기 전에 계약 검사), heartbeat
├─ store/     Zustand. 셀별 상태(task, 제안·수렴, 진행률, joints, alarms, metrics, 연결 상태)
├─ scene/     R3F 씬: 배경 GLB, 로봇(URDF), 작업판, 용접선, 마커, 카메라 프리셋, 선택
├─ lab/       트윈 랩: 씬만 띄우는 개발용 화면, 픽스처 재생기, window.__twin. 로봇 랩(/lab/robot): 로봇 하나와 관절 슬라이더
├─ panel/     로봇 목록·로봇 패널, 카메라 뷰, canvas 오버레이, 수정 모드(그리기), 작업 제어 버튼, 2D 상태 색(ui-state.ts)
├─ alarms/    알람 카드(활성 알람, 심각도순·최신순, 누르면 그 로봇)
└─ metrics/   신뢰도·추론 지연·외란 강도 칸
```

의존 방향: `scene / panel / alarms / metrics → store → bus`. 화면 컴포넌트는 MQTT를 직접 만지지 않는다(명령은 app이 넘겨준 bus로만).

## 데이터 흐름

```
수신: 브로커 → bus(토픽 파싱, 타입 검증) → store → 화면
송신: 버튼·드래그 → bus.publish(cmd/…) → (서버 처리) → task/state 수신 → 화면 변경
영상: <img src="/stream/{cell}"> 위에 canvas를 겹쳐 경로를 그림
```

## 핵심 규칙

- 명령을 보낸 직후 화면을 미리 바꾸지 않는다. 서버의 `task/state`를 받은 뒤에 바꾼다.
- 버튼 활성화는 서버 상태에서만 계산한다.
- 관절각처럼 자주 오는 데이터는 React 리렌더 없이 `useFrame`에서 store를 직접 읽고 보간한다.
- 토픽의 `{site}/{cell}`로 store의 셀과 씬의 객체를 찾는다. 사이트별 분기 코드를 쓰지 않는다.
- 붉은 경로선은 브라우저가 canvas에 그린다. 좌표는 원본 프레임 픽셀로 보관하고, 그릴 때만 화면 크기로 변환한다.
- 입력은 Pointer Events 하나로 마우스·터치·펜슬을 처리한다. 수정 모드에서는 페이지 스크롤을 막는다.
- 드래그 중의 선은 프론트 혼자 그리고, 손을 뗄 때 한 번만 `cmd/drag`를 보낸다.
- 긴급정지 버튼은 모든 화면에 고정한다.
- 서버나 브로커와 끊기면 화면에 표시하고, 다시 붙으면 retained 상태로 복구한다.

## 작업 순서

서버 전 프론트 단계의 기능명세·검증·마일스톤(F0~F5)은 [spec.md](spec.md). 서버 자리는 MQTT Mock 서버, 카메라 자리는 임의의 사진이다.

1~8번(bus·store, 패널, 씬, 선택·알람, 수정 모드, 긴급정지·연결 상태, 메트릭, 카메라 프리셋·태블릿)은 F0~F4로 끝났다(2026-11-19). 사이트는 주소의 `?site=` 또는 `VITE_DEFAULT_SITE`로 고른다(Mock 서버가 한 번에 한 사이트를 돌린다). 남은 것은 태블릿 사람 확인과 F5(실제 서버·카메라)다.
